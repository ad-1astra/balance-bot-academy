Teacher Guide · Week 2

Balance Bot Academy turns Week 2: Instructions and Algorithms into four 3D games about our two-wheel self-balancing robot. Every mission can only be won by doing the idea: ordering steps, writing exact commands, choosing flowchart shapes, ordering code. Reading step: "An algorithm is a recipe."

Setting up the room

  • Works on laptops, tablets and phones, in any modern browser. Keep the folder together; it also runs offline (Three.js fallback in lib/).
  • Open the hub, add one player per student, and tap a name before that student plays. Progress is saved in this browser only, so a student who changes device starts again.
  • Pairs: one is the programmer, one reads the program aloud and predicts what the robot will do before Run. Swap every mission (this mirrors Program a Friend).
  • Juniors (6–12): Balance Loop 1–3, Path Coder 1–3, Flowchart Factory 1–2, First Program 1–2. Seniors (13–19): everything, including the Python missions and the boss maze.
  • End each session with its test in the Test Arena. Quiz Duel works on one keyboard (A S D F vs H J K L), good for show & tell.
  • Rules from the notes still apply: hands first, explain every line to your partner.

Ask while they play

  1. What is the difference between an instruction, an algorithm and a program?
  2. In Recipe Mix-Up, why did "Work out which way" first make the robot fall?
  3. Why does TURN LEFT not change the robot's square?
  4. Your robot bumped into a chair. Whose fault is it, the robot's or the program's?
  5. Why must the real robot loop so fast?

1: one step / all the steps in order, like a recipe / an algorithm written in code a computer understands. 2: there was no tilt reading yet, so there was nothing to think about. 3: a turn is a quarter turn on the spot. 4: the program's: computers follow the steps exactly, even wrong ones. That is a bug. 5: it tips over in a fraction of a second, so it must feel and correct the tilt hundreds of times a second.

Ask while they play

  1. Follow the arrows with your finger: what happens when the battery is not low?
  2. Which shape asks a question? How many arrows leave it?
  3. Juniors: which block starts a program? What did changing the order do?
  4. Seniors: what does print( ) do? Why did Python say "name is not defined"?
  5. What is one thing a computer can't guess?

1: No → Keep balancing. 2: the diamond; two (Yes and No). 3: "when ⚑ clicked"; the sprite went somewhere else or said things at the wrong time. 4: shows words on the screen; the line using name ran before the input( ) line gave it a value. 5: anything you didn't write down: how far, which way, what comes next.

Quick quiz (from the notes) · answers

  1. What is an algorithm? A list of clear steps, in the right order, that solves a problem.
  2. Why does order matter? Change the order and the result changes; the robot falls.
  3. In the friend game, what is a bug? A wrong (or missing) step in the program.
  4. Which shape asks a yes/no question? The diamond.
  5. Juniors: which block starts a program? "when ⚑ clicked". Seniors: what does print( ) do? Shows words on the screen.
